# Day 1 —— 与 Claude Code 的第一次对话

[返回 Day 0（安装）](../day0/README.md)

---

你已经安装了 Claude Code。接下来做什么？本指南带你了解三个使用层次 —— 每一层让你对 Claude **如何** 工作有更多控制。

想象雇人：
1. **提示** = 在街上问路人方向
2. **代理** = 雇佣一个总是按特定方式做事的专家
3. **Skills** = 该专家对特定任务有特定训练

---

## 层次 1：提示（直接问）

> 🧠 **想象** 给知识很多的朋友发短信。你问 "卡拉奇天气怎么样？" 他们会给你一个答案 —— 但你不知道他们是否查了天气应用、看了窗外，还是从记忆猜测。

打开终端输入 `claude`。你现在在对话中。尝试输入：

```
卡拉奇天气怎么样？
```

Claude 会回答 —— 但**如何**回答不可预测。可能：
- 从训练数据提取（可能过时）
- 搜索网络（如果有 web 工具）
- 给你通用答案而非实时数据

这对快速问题完全没问题！但如果需要**一致、可靠的结果**，仅提示不够。

### 提示何时好用

- 问代码库问题（"这个文件做什么？")
- 写或编辑文档（"重写这邮件让它更专业")
- 头脑风暴（"给我5个这个活动的主题行")
- 解释事物（"像我不是开发者一样解释这个错误消息")

### 局限

每次你问 "天气怎么样？"，Claude 可能以不同方式获取数据 —— 或根本不获取真实数据。不保证用相同来源或方法两次。

## 层次 2：代理（专家）

**代理** 是 Claude 扮演特定角色 ——像分配工作头衔。

> 🧠 **想象** 餐厅厨房。没有代理，你走进随机厨房喊 "给我做意面！" —— 听到的人可能煮方便面或做五道意大利菜。有了代理，你雇**意面厨师**，工作描述说："总是用新鲜食材，总是煮 al dente，总是按同样方式摆盘。" 现在你每次都知道会得到什么。

同样的想法应用到 Claude：

> **没有代理：** 你问 Claude "迪拜天气怎么样？"
> 它可能查训练数据、搜索网络或猜测。你不知道它会做什么。
>
> **有了代理：** `weather-agent` 有清晰工作描述：
> *"总是查 Open-Meteo API 获取迪拜。总是返回特定格式的温度。"*
> 同样问题，同样方法，每次一样。

### 本仓库的真实示例

本仓库有个 `weather-agent` —— 它的全部工作是获取迪拜温度。以下是它与仅提示的区别：

| | 提示 | 代理 |
|---|---|---|
| **来源** | 可能任意 | 总是 Open-Meteo API |
| **位置** | Claude 选的 | 总是迪拜（lat: 25.2, lon: 55.3） |
| **格式** | 随机段落 | 清洁温度 + 单位 |
| **一致性** | 每次不同 | 同样方法，每次 |

### 结论

代理给你**可预测性**。同样问题 → 同样方法 → 同样质量。优势不在于代理更聪明，而是**一致**。

## 层次 3：Skills（训练）

**Skill** 是代理（或 Claude 本身）可用的特定能力。

> 🧠 **想象** 新员工的培训手册。某人加入团队时，他们有角色（代理），但也经过特定培训模块 —— 如何用 CRM、如何写提案、如何开站会。每个培训模块是 **skill**。角色告诉他们**是什么**；skills 告诉他们**如何做特定事**。

想想真实的人：

> **Shayan** 有很多 skills：
> - 工程 skill —— 能写代码
> - 游戏 skill —— 知道游戏机制
> - 阅读 skill —— 能消化和总结长文档
>
> 每个 skill 有自己的知识和方法。Shayan 对正确任务用正确 skill。

Claude 同样工作。`weather-agent` 有个叫 `weather-fetcher` 的 skill：

- **代理**（`weather-agent`) = 有 "天气报告员" 工作头衔的人
- **skill**（`weather-fetcher`) = 关于**如何**获取天气数据的具体培训

skill 包含确切指令：
1. 调用这个特定 API URL
2. 从响应的这个特定字段提取温度
3. 以这个特定格式返回

### 为什么分开代理和 Skills？

因为**一个代理可以有多个 skills**，**一个 skill 可被多个代理使用**。

例如，想象你创建：
- 一个 `daily-report-agent` 总结你的一天
- 它可以用 `weather-fetcher` skill（天气）+ `calendar-reader` skill（会议）+ `email-summarizer` skill（邮件亮点）

Skills 是可复用构建块。代理是使用它们的人。

---

## 整合在一起

完整图景：

```
层次 1：提示
你 → "天气怎么样？" → Claude 某种方式搞定
                       （不可预测方法）

层次 2：代理
你 → 天气代理 → 总是用同样方法
                （可预测方法）

层次 3：Skills
你 → 天气代理 → 用 weather-fetcher skill
                （可预测方法 + 特定指令）
```

每层增加更多控制：

| 层次 | 你控制什么 | 最适合 |
|-------|-----------------|----------|
| **提示** | 问题 | 快速一次性问题 |
| **代理** | 问题 + 谁回答 | 可重复任务 |
| **Skills** | 问题 + 谁回答 + 如何做 | 关键工作流 |
